ana-channel-test

채널 왕복 진단
대시보드 ↔ 브리지 ↔ fakechat ↔ Claude Code 세션의 채팅 왕복이 제대로 되는지 단계별로 진단합니다.

① 연결 상태 (2.5초마다 자동 갱신)

1. 앱 서버확인 중…
2. 브리지확인 중…
3. fakechat :8787확인 중…
4. 두뇌 응답확인 중…

② 왕복 테스트

③ 설정 가이드 (처음부터 순서대로)

  1. 플러그인 설치(최초 1회): claude plugin install fakechat@claude-plugins-official
  2. 앱 서버: 이 디렉토리에서 node server.js → 이 페이지(http://localhost:8808)가 뜨면 신호등 1이 초록.
  3. 두뇌 세션(별도 터미널): ./brain.sh — 고아 fakechat을 정리한 뒤 claude --channels plugin:fakechat@claude-plugins-official를 실행한다. 세션 배너에 "Channels (experimental) …" 문구가 보여야 하고, 신호등 3이 초록이 된다.
  4. 브리지(별도 터미널): node fakechat-bridge.js → "fakechat 연결됨" 로그가 뜨고 신호등 2가 초록.
  5. 왕복 확인: 위의 핑 테스트 버튼. 두뇌 세션이 채널 메시지를 받아 POST /api/agent로 응답하면 신호등 4가 초록이 되고 왕복 시간이 표시된다. (이 앱의 CLAUDE.md가 세션에 핑 응답 규칙을 자동으로 알려준다.)

채널이 붙는 시점은 세션 기동 시점뿐이다 — 플래그 없이 띄운 세션에는 나중에 채널을 붙일 수 없다.

④ 트러블슈팅

신호등 3이 빨강/주황 — fakechat이 없거나 고아다
  • 주황(고아 의심): 이전 세션이 남긴 bun 서버가 8787을 점유했을 수 있다. 새 세션의 fakechat은 EADDRINUSE로 조용히 죽는다(/mcp에 -32000). 핑이 성공하면 사용 중인 것이니 유지하고, 실패하면: 
    lsof -iTCP:8787 -sTCP:LISTEN -n -P   # 부모(PPID)가 1(launchd)이면 고아
kill <PID>                            # 고아 제거 후 세션 재시작 (또는 처음부터 ./brain.sh 사용)
  • 빨강(리스너 없음): 세션이 --channels 없이 떴거나 fakechat 기동 실패. 세션에서 /mcp로 상태 확인 → 실패면 세션 종료 후 ./brain.sh로 재기동.
  • MCP 로그 직접 확인: 
    ls -t ~/Library/Caches/claude-cli-nodejs/*/mcp-logs-plugin-fakechat-fakechat/*.jsonl | head -1 | xargs tail -5
신호등 2가 빨강 — 브리지가 안 돌거나 서버를 못 찾는다
  • node fakechat-bridge.js가 실행 중인지 확인. "fakechat 끊김, 2s 후 재접속" 루프면 문제는 브리지가 아니라 신호등 3(fakechat)이다.
  • 포트가 다르면 DASH_URL=http://127.0.0.1:8808 node fakechat-bridge.js.
신호등 4가 빨강 — 메시지는 가는데 응답이 안 온다
  • 이분 탐색(가장 빠름) — 브리지를 건너뛰고 채널에 직접 주입: 
    curl -s -X POST localhost:8787/ -F 'id=diag-1' -F 'text=진단'
    세션 화면에 "진단"이 뜨면: 채널·세션은 정상 → 남은 원인은 세션이 응답을 POST /api/agent로 안 보내는 것. 세션에 역할 지시가 들어갔는지(이 디렉토리의 CLAUDE.md를 읽고 떴는지) 확인.
    안 뜨면: 세션이 채널을 물지 않았다 → 신호등 3 항목으로.
  • 세션이 fakechat의 reply 툴로만 답하면 대시보드에는 아무것도 안 보인다 — 응답은 반드시 POST /api/agent(필드명 text).
중간 과정·최종 응답이 채팅창에 안 보인다 (미러 훅)
  • 이 앱은 .claude/settings.json 훅(tools/mirror-hook.mjs)이 세션의 텍스트·도구 활동을 자동 미러한다. 훅은 세션 기동 시점에 로드되므로 설정 변경 후엔 세션 재시작.
  • 턴 마지막 텍스트는 Stop 훅 또는 배달 보증 watcher(최대 ~3초 지연)가 전달한다. 안 오면 훅 로그 확인: 
    cat /tmp/ana-channel-test-mirror.log
  • 수동 curl 응답과 미러가 겹치면 같은 내용이 두 번 보인다 — 미러가 살아 있으면 세션은 그냥 평소처럼 대답만 하면 된다.
수동 점검 명령 모음 
# 1. 서버 살아있나
curl -s localhost:8808/api/health | python3 -m json.tool

# 2. 인박스에 쌓이나 (브리지 없이)
curl -s -X POST localhost:8808/api/chat -H 'content-type: application/json' -d '{"text":"ping"}'
curl -s --max-time 3 localhost:8808/api/inbox-wait   # {"messages":[...]} 면 서버 정상

# 3. 피드 확인 (응답이 서버까지는 왔나)
curl -s "localhost:8808/api/feed?since=0" | python3 -m json.tool

# 4. 에이전트 응답 경로 수동 테스트
curl -s -X POST localhost:8808/api/agent -H 'content-type: application/json' -d '{"text":"수동 응답 테스트"}'

⑤ 이 진단이 커버하는 경로

[이 페이지] → POST /api/chat → 서버 inbox → (신호등2) fakechat-bridge 롱폴
    → WS 주입 → (신호등3) fakechat :8787 → MCP 알림 → Claude 세션
    → CLAUDE.md 역할 규칙 → POST /api/agent → (신호등4) 피드 → 이 페이지
